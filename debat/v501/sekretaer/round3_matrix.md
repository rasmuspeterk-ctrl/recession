*Written by Claude, who is a party to this debate. Positions below are quoted or closely paraphrased from Rounds 1–2; the grouping into SETTLED / OPEN and the proposed resolutions are Claude's and may be challenged.*

## SETTLED (no councillor dissents after Round 2)

- **S1 Spine.** Stitch, no rebuild. Yale file kept in-repo, immutable, under its own name; a separately named composite with a provenance column per row; Shiller rows through 2023-07 byte-identical; 2023-08/09 replaced by FRED SP500 monthly mean + CPIAUCNS + multpl CAPE. Tolerances asserted in tests: SP500 median |dev| ≤ 0.1 %, ≥ 99 % of months within 1 %; CAPE median |dev| ≤ 0.1 %, max 1 % outside the two documented preliminary months; every exception documented. multpl parsed with hard assertions on row count and first date, page bytes hashed, diff-marked like FRED.
- **S2 Two spine tests, not one** (Astra's refinement, adopted by Kimi and Gemini): (a) *legacy replay* — the frozen Yale inputs through the old chain must reproduce w = [−2.1755, −1.6907], n_obs 264 exactly; (b) *correction bridge* — the corrected spine truncated at 2023-09 is run and any difference to (a) is measured and reported, not required to be zero.
- **S3 Cadence.** Monthly re-anchoring is dead. Weights, standardisation and the fitted base rate are frozen between re-anchor events. Every ledger row carries an 8-character hash of a calibration manifest (code version, snapshot hash, announcement-table hash, train-end, n_obs, w, standardisation, base rate); the manifest file is committed. A bridge row at each splice prints P under both old and new weights on the same inputs.
- **S4 Episode table.** 12 onset rows + one row with all negative origins; per-row additive log-loss contribution 100·Σ(L0−Lm)/ΣL0 that sums exactly to the pooled improvement; Brier and counts per row; negatives also by the existing chronological bootstrap blocks, whose boundaries are published and never re-optimised. LOEO printed as sensitivity only (no future training data), never co-primary.
- **S5 Paired rule construction.** Δ_b = P_b(x_now) − base_b over the existing episode-block bootstrap draws, paired by draw; the 10–90 % band (80 % coverage — say so) excluding zero is the supplementary criterion. Printed beside Section 6; Section 6's verdict and ratio suppression unchanged in this release. Gemini's historical paired-loss bootstrap is a *skill* diagnostic and goes next to the MDE, not into the verdict.
- **S6 Claims erratum.** Fix `monthly_mean`, re-run the claims_mom test exactly as preregistered, no tuning; publish −61.9pp as "superseded implementation result" beside the corrected number; rejection or not, no promotion; plus a pipeline-wide audit of the aggregation bug class across all 20 series and 3 manual inputs, with an aggregation test. (Gemini conceded in Round 2.)
- **S7 Framing.** v5.0.1 is a data-and-estimation repair, not a skill change. Staged bridge at a fixed current input vector (Astra); walk-forward published twice — truncated vs extended panel (Kimi); common-origin and added-origin skill reported separately. Mandatory sentence: a lower (or higher) recalibrated P is changed estimation, not changed economic risk.
- **S8 Integrity rules.** Feature search stays closed. The gate (curve-only vs full model) is re-run on the extended panel and republished, but its outcome **cannot** change the operational model in v5.0.1: if the full model wins by more than the MDE, that triggers a council decision for a v5.1 protocol, never an automatic switch. Exact dated eligibility audit of new origins before fitting. Origins inside the 18-month floor are NaN, never 0 (test). At a refit, n_obs must grow by exactly the audited number of new origins, else fail (this replaces the bare "weights must change" alarm). Synthetic-observation ingestion test. Base rate: expanding intercept inside the walk-forward; frozen calibration parameter in the verdict.
- **S9 Staleness guard.** Hard fail on stale inputs, with *source-specific* expected maximum age (Astra's refinement of Kimi's 45 days): e.g. daily ≤ 7 d, weekly ≤ 14 d, monthly ≤ 45 d, quarterly ≤ 130 d.

## OPEN

**O1 — Row universe (Q2).** *Astra:* estimation on each model's own features; comparisons on the intersection E_A∩E_B; vetoes "BASE10-driven operational eligibility" — the operational model must not be hostage to a CAPE scraper it does not use. *Gemini:* single common mask; a production model estimated on a different sample than the gated one "destroys the audit trail"; vetoes E_A ≠ E_AB. *Kimi:* common mask; pairwise intersections mean up to 28 evaluation samples with no MDE; zero origins gained. *Claude (R2 compromise):* row-universe START fixed at 1947Q2 as a protocol constant (so the legacy replay holds); each model's estimation END set by its own features + label; the gate comparison **requires identical origins and fails loudly** ("comparison unavailable") if they differ — no pairwise samples, no dual estimates. Today the assertion passes trivially; if multpl breaks, curve-only keeps running and the gate line says so.
→ *Proposed resolution:* Claude's compromise. It gives Astra the robustness (no CAPE hostage), Gemini the guarantee that any printed gate is on identical origins with the production estimate, Kimi no pairwise samples. Councillors: can you live with it?

**O2 — Oracle-free supplement label (Q4c).** *Astra, Gemini, Claude (R2):* the model's own label — new onset within 4 quarters — with real-time censoring (announcement table as of the origin), mature labels only, identical coverage for the baseline, unreconstructable origins reported. *Gemini's mechanism against Y′:* in month 6 of a recession the curve has re-steepened; scoring P≈5 % against Y′=1 is structural negative skill for a forward-onset model. *Kimi (moved to Y′ in R2):* under the strict label, 2008Q2-type origins are scored as misses that live users experienced as hits. *Gemini's zero-imputation:* rejected by Astra and Kimi (no announcement ≠ Y=0; violates the 18-month floor) and not repeated by Gemini in R2.
→ *Proposed resolution:* strict onset label + real-time censoring, **and** a separately printed line: the count of in-recession-but-unannounced origins scored and their loss contribution, so the "correct but late" penalty Kimi describes is visible rather than hidden. Kimi: does disclosure satisfy the 2008Q2 concern, or do you veto?

**O3 — NBER-triggered refit (Q3).** *Astra:* NBER-table changes update eligibility and scoring only; weights refit annually in September; no unscheduled refits. *Gemini, Kimi, Claude:* refit on NBER-table change or annually, whichever first.
→ *Proposed resolution:* annual refit every September; an NBER announcement (new peak or trough) additionally triggers a refit, but only as a fully versioned event with the same manifest and bridge as the annual one — i.e. documented, never automatic or silent, which is what Astra's veto actually targets. Astra: acceptable?

**O4 — Paired-rule endgame (Q4b).** *Astra:* no automatic replacement after twelve months. *Gemini (R2):* parallel publication for 12 months, then replace. *Kimi:* 12 months parallel **plus** a full walk-forward backtest of both rules; then the council votes with the disagreement rate in hand. *Claude:* withdrew automatic replacement; separate future council decision with a preregistered criterion.
→ *Proposed resolution:* supplement only in v5.0.1; both rules backtested over the full walk-forward now and the disagreement rate published; any change of the verdict rule is a separate, later council decision — nothing automatic. Gemini: acceptable?

**O5 — Direction prediction (Q6).** *Kimi:* state before the run that curve coefficient, skill and P should fall. *Astra:* none is guaranteed (Δβ>0 with z<0 lowers P only holding intercept, standardisation and sample fixed).
→ *Proposed resolution:* the README states Kimi's expected direction *before* the run, labelled as a falsifiable prediction with Astra's caveat, and the bridge table then shows the outcome.

**O6 — Outlier guards on CAPE (Q7).** *Kimi:* level 5–60 and m/m change < 15 % as hard guards. *Astra:* extreme genuine market moves trigger review, not automatic rejection.
→ *Proposed resolution:* the guard fails the snapshot **unless** the run is repeated with an explicit `--accept-outlier` flag, which is recorded in meta.json — review with a paper trail, never a silent pass, never a permanent block during a real crash.

**O7 — Trivial.** Anchor month: September (Astra, Gemini; Claude moved). Kimi's rolling 12 months collapses to the same thing after the first September.
